# 03 · 使用与验证手册

---

## 1. 五分钟上手

```bash
TOOL=/usr/local/bin/vmbackup-partition
VM_DATA=/var/lib/victoria-metrics-data          # vmstorage 的 -storageDataPath
SNAP_API=http://127.0.0.1:8482/snapshot/create # vmstorage 的 HTTP 端口

# ① 先看计划（不需要 -dst，也不需要远端凭据，不写任何数据）
$TOOL -storageDataPath=$VM_DATA \
      -snapshot.createURL=$SNAP_API \
      -fromMonth=2026_02 -toMonth=2026_06 \
      -dryRun -planOut=/tmp/plan.json

# ② 确认无误后正式备份
$TOOL -storageDataPath=$VM_DATA \
      -snapshot.createURL=$SNAP_API \
      -fromMonth=2026_02 -toMonth=2026_06 \
      -dst=fs:///backup/vmstorage-0 -concurrency=10

# ③ 用官方 vmrestore 还原（官方工具无需任何改动）
vmrestore -src=fs:///backup/vmstorage-0 -storageDataPath=/var/lib/victoria-metrics-restored
```

## 2. 命令行参数

### 2.1 本工具新增参数

| 参数 | 类型 | 默认 | 说明 |
| --- | --- | --- | --- |
| `-fromMonth` | string | **必填** | 起始月份（闭区间）。接受 `YYYY_MM` / `YYYY-MM` / `YYYYMM` 三种写法 |
| `-toMonth` | string | **必填** | 结束月份（闭区间）。格式同上。若早于 `-fromMonth` 立即报错退出 |
| `-includeNonPartitioned` | bool | `true` | 是否保留非月份分区文件（主要是 `metadata/` 下的租户与索引元数据）。**强烈建议保持 true** |
| `-prune` | bool | `true` | 是否删除目标端存在、而本次备份范围内不存在的 part（把目标端对齐到本次范围）。语义与官方 vmbackup 一致 |
| `-dryRun` | bool | `false` | 只列举快照并输出备份计划，不产生任何远端写入；该模式不需要 `-dst` |
| `-allowEmptyResult` | bool | `false` | 当区间内**没有任何按月分区的 part** 时是否允许继续。默认拒绝（防止写出还原后无数据的无效备份） |
| `-expectMonths` | string | 空 | 安全护栏：逗号分隔的月份列表（如 `2026_02,2026_03`）。若快照中缺失其中任一月，立即报错退出 |
| `-planOut` | string | 空 | 把备份计划以 JSON 写入指定文件，便于审计与自动化比对 |

### 2.2 完整兼容官方 vmbackup 的参数

| 参数 | 默认 | 说明 |
| --- | --- | --- |
| `-storageDataPath` | `victoria-metrics-data` | 必须与 vmstorage / VictoriaMetrics 的该参数一致 |
| `-snapshotName` | 空 | 使用既有快照。与 `-snapshot.createURL` 互斥 |
| `-snapshot.createURL` | 空 | 自动创建快照，例 `http://vmstorage:8482/snapshot/create` |
| `-snapshot.deleteURL` | 空 | 未指定时自动由 `createURL` 推导（`/create` → `/delete`）；创建的快照会在备份结束后自动删除 |
| `-dst` | 空 | 目标端。`fs://` `s3://` `gs://` `azblob://` |
| `-origin` | 空 | 旧备份位置，用于**服务端拷贝**加速全量备份（免下载） |
| `-concurrency` | `10` | 并发工作协程数 |
| `-maxBytesPerSecond` | `0` | 上传限速（如 `50MB`）；`0` 表示不限速 |
| `-httpListenAddr` | `:8420` | `/metrics` 暴露地址 |
| S3 / GCS / AzBlob 全套参数 | — | 如 `-customS3Endpoint`、`-s3ForcePathStyle`、`-credsFilePath` 等，解析逻辑完全复用官方实现 |

## 4. 执行备份

### 4.1 单节点（本地磁盘目标端）

```bash
vmbackup-partition \
  -storageDataPath=/var/lib/victoria-metrics-data \
  -snapshot.createURL=http://127.0.0.1:8482/snapshot/create \
  -fromMonth=2026_02 -toMonth=2026_06 \
  -dst=fs:///backup/vmstorage-0 \
  -concurrency=10 \
  -expectMonths=2026_02,2026_03,2026_04,2026_05,2026_06
```

日志中的完成行：

```
备份完成：/var/lib/…/snapshots/20260921120000-1A2B3C4D → fsremote "/backup/vmstorage-0"；
目标端共 92 个 part (430.78KiB)；删除 0 个 (0B)；服务端拷贝 0 个 (0B)；上传 92 个 (430.78KiB)；耗时 0.296s
```

### 4.2 单节点（S3 / MinIO 目标端）

```bash
export AWS_ACCESS_KEY_ID=...  AWS_SECRET_ACCESS_KEY=...

vmbackup-partition \
  -storageDataPath=/var/lib/victoria-metrics-data \
  -snapshot.createURL=http://127.0.0.1:8482/snapshot/create \
  -fromMonth=2026_02 -toMonth=2026_06 \
  -dst=s3://my-bucket/vm-cluster/2026H1/vmstorage-0 \
  -customS3Endpoint=http://minio.internal:9000 \
  -s3ForcePathStyle \
  -concurrency=10   -maxBytesPerSecond=100MB
```

### 4.3 三节点集群（推荐用编排脚本）

VictoriaMetrics 集群版中**每个 vmstorage 的数据相互独立**，必须分节点备份、分节点写入**各自独立的目标目录**。

```bash
bash scripts/backup-cluster.sh \
  --node vmstorage-0=10.0.0.11 \
  --node vmstorage-1=10.0.0.12 \
  --node vmstorage-2=10.0.0.13 \
  --ssh-user root \
  --tool /usr/local/bin/vmbackup-partition \
  --storage-data-path /var/lib/victoria-metrics-data \
  --vmstorage-port 8482 \
  --from-month 2026_02 --to-month 2026_06 \
  --dst-prefix s3://my-bucket/vm-cluster/2026H1
```

脚本会在每个节点上执行：

```
<tool> -storageDataPath=<path> \
       -snapshot.createURL=http://127.0.0.1:<port>/snapshot/create \
       -fromMonth=… -toMonth=… -concurrency=10 -prune=true \
       -dst=<dstPrefix>/<nodeName>
```

加 `--dry-run` 可以先在三个节点上同时输出计划（不写目标端、不需要远端凭据）。

**各节点写入的目标目录：**

```
s3://my-bucket/vm-cluster/2026H1/vmstorage-0/
s3://my-bucket/vm-cluster/2026H1/vmstorage-1/
s3://my-bucket/vm-cluster/2026H1/vmstorage-2/
```

> ⚠️ **三个节点的备份绝不能写入同一个目录**。不同 vmstorage 上可能出现**相同的 part 路径但内容不同**，混写会因 `-prune` 差集计算而互相删除/覆盖。

### 4.4 备份产物结构

```
<dst>/
├── backup_complete.ignore        ← 完成标记（官方 vmrestore/vmbackup 均识别）
├── backup_metadata.ignore        ← 官方格式的备份元数据（created_at / completed_at）
├── backup_month_range.ignore     ← 本工具新增：月份选择审计记录

```

## 5. 还原与验证

### 5.0 还原前必须知道的两件事（否则会丢数据）

#### ① 启动后必须调大 `-retentionPeriod`

VictoriaMetrics 的保留期清理**在后台 merge 时生效**：分区内某个 part 的 `MaxTimestamp`
早于 `now - retentionPeriod`，该 part 就会被丢弃
（`lib/storage/partition.go`：`retentionDeadline := timestampFromTime(startTime) - pt.s.retentionMsecs`）。

按月备份装的是**过去**的月份，用默认的 `-retentionPeriod=1M` 启动，等于让引擎把刚还原的数据清空。

**实测（v1.150.0，还原 `2026_02`~`2026_06` 后用默认保留期启动）：**

```
t=0s    可查=[2026_02 2026_03 2026_04 2026_05 2026_06]   磁盘分区=[2026_02 .. 2026_06 2026_09]
t=50s   可查=[2026_02 2026_03 2026_04 2026_05 2026_06]   磁盘分区=[2026_02 .. 2026_06 2026_09]
t=75s   可查=[]                                           磁盘分区=[2026_09]
```

约 1 分钟后历史分区被全部删除。用 `-retentionPeriod=100y` 启动则数据完整保留。

→ **归档/导入场景请显式指定覆盖数据跨度的保留期**，例如 `-retentionPeriod=100y`。
参考：<https://docs.victoriametrics.com/victoriametrics/single-server-victoriametrics/#retention>

#### ② 不要还原进一个已经在用的数据目录

官方文档明确：`-storageDataPath` 目录非空时，其内容会被备份内容同步替换，
**效果等同于 `rsync --delete`**（<https://docs.victoriametrics.com/victoriametrics/vmrestore/>）。

如果目标节点已承载当前月数据，还原会删掉备份里没有的月份。导入新集群请使用空目录。

### 5.1 用官方 vmrestore 还原（不改任何官方代码）

```bash
# 各节点分别还原到该节点自己的目录
vmrestore -src=s3://my-bucket/vm-cluster/2026H1/vmstorage-0 \
          -storageDataPath=/var/lib/victoria-metrics-data

# 单机版直接启动即可查询（注意 retentionPeriod）
victoria-metrics -storageDataPath=/var/lib/victoria-metrics-restored \
                 -httpListenAddr=:8428 -retentionPeriod=100y
```

### 5.2 还原后的验证清单

```bash
# ① 目标端只剩所选月份
find <restoredDataPath>/data -maxdepth 2 -mindepth 2 -type d | sort
#    期望只列出 2026_02 … 2026_06

# ② 查询数据，确认排除的月份不可见
curl -s 'http://localhost:8428/api/v1/label/month/values' | jq
#    期望："data": ["2026_02","2026_03","2026_04","2026_05","2026_06"]

curl -s 'http://localhost:8428/api/v1/series?match[]={__name__!=""}' | jq -r '.data[].month' | sort -u

# ③ 确认排除月份无数据
curl -s 'http://localhost:8428/api/v1/query?query=count({month="2026_01"})' | jq
#    期望：result 为空数组
```

## 7. 运维场景

### 7.1 多批不同月份累积到同一目标端

```bash
# 第一批：02..06
$TOOL … -fromMonth=2026_02 -toMonth=2026_06 -dst=fs:///backup/vm-0 -prune=true

# 第二批：07..09 追加，必须显式关闭 prune
$TOOL … -fromMonth=2026_07 -toMonth=2026_09 -dst=fs:///backup/vm-0 -prune=false
```

**`-prune=false` 是硬性要求。** 若沿用默认 `-prune=true`，第二批会把第一批的 `02..06` 全部删除。为降低误操作风险，本工具在 `-prune=true` 且差集中含有"月份范围之外"的 part 时会主动告警：

```
warn  目标端 fsremote "/backup/vm-0" 中有 90 个 part 位于所选月份范围 2026_07..2026_09 之外，本次将被删除（-prune=true）。
      若你希望通过多批不同月份范围累积到同一个 -dst，请显式设置 -prune=false
```

### 7.2 增量备份

把 `-dst` 指向**上一次的备份目录**，本工具会只上传差集（`PartsDifference(kept, dstParts)`），等价于官方 vmbackup 的增量语义：

```bash
$TOOL … -fromMonth=2026_02 -toMonth=2026_06 -dst=fs:///backup/vm-0   # 第二次执行即增量
```

### 7.3 用 `-origin` 加速

`-origin` 指向旧备份，本工具会先尝试**服务端拷贝**（不落地、不耗出口带宽），剩余部分才上传。若 origin 与 dst 后端类型不同导致 `CopyPart` 失败，会自动退化为"下载再上传"：

```bash
$TOOL … -dst=s3://bucket/new/vm-0 -origin=s3://bucket/old/vm-0
```

### 7.4 用 `-expectMonths` 作为防呆护栏

**推荐始终加上。** 它能拦住"月份记错"这一类最难发现的错误：

```bash
$TOOL … -fromMonth=2026_02 -toMonth=2026_06 \
       -expectMonths=2026_02,2026_03,2026_04,2026_05,2026_06
```

若快照中实际不存在其中任一月，立即报错退出，**不写目标端**：

```
fatal  试运行失败: 快照 "/var/lib/victoria-metrics-data/snapshots/20260921120000-1A2B3C4D" 中缺失期望存在的月份 [2026_10]；
       快照实际存在的月份为 [2026_01 2026_02 2026_03 2026_04 2026_05 2026_06 2026_07 2026_08 2026_09]。
       请核对 -fromMonth/-toMonth，或先用 -dryRun 查看数据分布
```

> 前缀会随模式变化：`-dryRun` 下为 `试运行失败:`，正式备份下为 `备份失败:`；而"缺参数/区间反转"这类发生在参数解析阶段的错误，前缀是 `参数校验失败:`。

## 8. 参数护栏一览（负向测试全部通过）

| 场景 | 行为 |
| --- | --- |
| 未提供 `-fromMonth` 或 `-toMonth` | 报错退出 |
| `-toMonth` 早于 `-fromMonth` | 报错退出 |
| `-snapshotName` 指向不存在的快照 | 报错退出 |
| 同时设置 `-snapshot.createURL` 与 `-snapshotName` | 报错退出 |
| `-dst` 位于 `-storageDataPath` 内部 | 报错退出（防止把备份写进数据目录） |
| `-origin` 与 `-dst` 指向同一位置 | 报错退出 |
| `-concurrency <= 0` | 报错退出 |
| `-expectMonths` 中某月缺失 | 报错退出，**不创建目标端** |
| 区间内没有任何按月分区的 part | 报错退出，**不创建目标端**；`-allowEmptyResult` 可显式放行并给出 WARN |
| `-dryRun` 未提供 `-dst` | 正常执行（试运行不需要目标端） |

## 9. 故障排查

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| `月份区间 … 中没有任何按月分区的数据 part` | 月份记错，或 `-storageDataPath` 指错 | 先跑 `-dryRun` 看 `snapshot total` 里到底有哪些月份 |
| 备份完成后目标端月份比预期多 | `-toMonth` 写成跨年了 | 核对区间；`-expectMonths` 可提前拦住 |
| 目标端原有月份被删除 | 用了默认 `-prune=true` 做多批累积 | 加 `-prune=false`；或从告警日志确认删除范围 |
| 快照创建后未删除 | 进程被 `kill -9` | 手工调 `http://<vmstorage>:8482/snapshot/delete?snapshot=<name>`；或用 `http://<vmstorage>:8482/snapshot/list` 查看残留 |
| 还原后存储启动报 metadata 缺失 | 用了 `-includeNonPartitioned=false` | 重跑备份并保持默认 `true` |
| `-dst` 被拒绝，提示位于数据目录内部 | 目标端路径在 `-storageDataPath` 之下 | 换到数据目录之外 |
| 备份耗时过长 | `-concurrency` 过低或未限速导致被上游限流 | 提高 `-concurrency`；用 `-maxBytesPerSecond` 主动限速避免打满链路 |
| 日志里的 `-snapshot.createURL` 显示为 `***` | 官方 `RegisterSecretFlag` 的脱敏行为，避免凭据进日志 | 正常现象 |

排查入口：加 `-httpListenAddr=:8420` 后访问 `http://localhost:8420/metrics`，可看到上传耗时、part 计数等运行指标。
