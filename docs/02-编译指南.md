# 02 · 编译指南

> 交付目标平台：**linux/amd64**。本文档同时说明本机（darwin/arm64）开发编译路径与真实环境所需的信息。

---

## 1. 前置条件

| 项目 | 要求 | 说明 |
| --- | --- | --- |
| Go 工具链 | **≥ 1.26.6** | 上游 VictoriaMetrics v1.150.0 的 `go.mod` 声明 `go 1.26.6`，低于此版本无法编译 |
| Git（可选） | 任意 | 只有在需要用本地源码检出做 `replace` 时才需要 |
| 网络（首次） | 可访问 Go 模块代理 | 本项目**没有** vendor 目录，依赖通过模块代理拉取 |
| 磁盘 | ≥ 1.5 GiB | 依赖缓存 + 构建缓存 |

核验 Go 版本：

```bash
go version          # 应输出 go1.26.6 或更高
go env GOTOOLCHAIN  # 建议为 local（见 §2 的坑）
```

## 2. 环境准备：Go 工具链的两个坑

### 坑 1 · `GOTOOLCHAIN=auto` 在 `GOSUMDB=off` 下会失败

如果本机 Go 版本低于 `go.mod` 声明的版本，Go 会自动去下载 `golang.org/toolchain@v0.0.1-go1.26.6.<os>-<arch>`。当环境里设置了 `GOSUMDB=off`（内网/代理环境常见）时，校验会直接失败：

```
go: downloading go1.26.6 (darwin/arm64)
go: download go1.26.6: golang.org/toolchain@v0.0.1-go1.26.6.darwin-arm64:
    verifying module: checksum database disabled by GOSUMDB=off
```

**两种解法，任选其一：**

**解法 A（推荐）· 手动安装指定版本工具链，然后固定为 `local`**

```bash
# 以阿里云镜像为例（内网可用官方 https://go.dev/dl/go1.26.6.<os>-<arch>.tar.gz 代替）
mkdir -p /opt/go-versions
curl -fL -o /tmp/go1.26.6.tar.gz \
  https://mirrors.aliyun.com/golang/go1.26.6.linux-amd64.tar.gz
tar -C /opt/go-versions -xzf /tmp/go1.26.6.tar.gz        # 得到 /opt/go-versions/go

# 使用
export GOTOOLCHAIN=local
export PATH=/opt/go-versions/go/bin:$PATH
go version                                                # go version go1.26.6 linux/amd64
```

> 注意：**必须同时设置 `GOTOOLCHAIN=local`**。否则 Go 仍会尝试联网下载工具链。

**解法 B · 让自动下载可用**

```bash
unset GOSUMDB            # 或 GOSUMDB=sum.golang.org
export GOFLAGS=
export GOTOOLCHAIN=auto
```

### 坑 2 · 修改 `go.mod` 里的 `go` 指令行不通（且不推荐）

把 `go.mod` 的 `go 1.26.6` 改低以绕过工具链要求，会在编译上游代码时触发大量语言特性/标准库 API 缺失错误，属于治标不治本。

**本项目的处理**：`go.mod` 中 `go 1.26.6` 保持与上游一致，不修改。

### 坑 3 · 依赖需要能拉到

```bash
go env GOPROXY   # 官方默认 https://proxy.golang.org,direct
                 # 内网可用 https://goproxy.cn,direct
```

首次构建前建议先预热依赖：

```bash
go mod download
```

## 3. 构建方式

仓库提供 `Makefile` 与脚本两条入口，三种构建路径。

### 3.1 方式一 · 标准构建（模块代理，推荐）

适用：**有外网 / 有可用 GOPROXY** 的构建机。依赖 `github.com/VictoriaMetrics/VictoriaMetrics v1.150.0` 从模块代理下载。

```bash
# 本机平台
make build

# 交叉编译到 linux/amd64（交付目标）
make build-linux-amd64

# 交叉编译到 linux/arm64
make build-linux-arm64

# 产出 + sha256 校验和
make release
```

等价的原生命令：

```bash
CGO_ENABLED=0 GOOS=linux GOARCH=amd64 go build -trimpath \
  -ldflags "-s -w -X 'github.com/VictoriaMetrics/VictoriaMetrics/lib/buildinfo.Version=vmbackup-partition v1.0.0 based-on VictoriaMetrics v1.150.0'" \
  -o bin/vmbackup-partition-linux-amd64 ./cmd/vmbackup-partition
```

指定 Go 的绝对路径（多版本共存时）：

```bash
make build-linux-amd64 GO=/opt/go-versions/go/bin/go
```

### 3.2 方式二 · 用本地官方源码检出构建（离线 / 锁定 commit）

适用：**无外网**，或需要把依赖锁定到某个具体 commit/私有魔改版。

```bash
git clone --depth 1 --branch v1.150.0 \
  https://github.com/VictoriaMetrics/VictoriaMetrics.git /opt/VictoriaMetrics

VM_SRC=/opt/VictoriaMetrics bash scripts/build-linux-amd64.sh
```

脚本的行为（**关键：不修改仓库内的 `go.mod`**）：

1. 读取仓库 `go.mod` / `go.sum`；
2. 生成一份临时 modfile（`mktemp -d`）并在末尾追加：

   ```
   replace github.com/VictoriaMetrics/VictoriaMetrics => /opt/VictoriaMetrics
   ```

3. 用 `go build -modfile=<临时文件>` 编译，退出时自动清理临时目录。

> 若本地官方源码目录带 `vendor/`，可叠加 `-mod=vendor` 实现完全离线。`scripts/build-vm-tools.sh` 就是这个模式。

### 3.3 方式三 · 构建官方对照工具（仅用于验证）

端到端验证需要官方 `victoria-metrics` / `vmrestore` / `vmbackup` 二进制做对照。官方仓库自带 `vendor/`，可完全离线构建：

```bash
VM_SRC=/opt/VictoriaMetrics \
OUT=$HOME/.cache/vmbackup-partition/vm-bin \
  bash scripts/build-vm-tools.sh
```

产物：

```
$HOME/.cache/vmbackup-partition/vm-bin/
├── victoria-metrics     # 产生真实存储与快照
├── vmrestore            # 还原本工具的备份（验证格式兼容）
└── vmbackup             # 全量对照备份（等价性断言）
```

> 这些二进制**不参与**本工具的构建，只是验证用的参照物。

## 4. 产物与校验

### 4.1 本次交付的实际产物

在本机（darwin/arm64，Go 1.26.6）交叉编译 linux/amd64 的结果：

```
文件   : bin/vmbackup-partition-linux-amd64
大小   : 46,612,642 字节
类型   : ELF 64-bit LSB executable, x86-64, version 1 (SYSV), statically linked, stripped
SHA256 : 58ba031c3898bc9827fe24c9ad400bbf0353ca6d150f6694522da3b75efcc7b3
版本串 : vmbackup-partition v1.0.0 based-on VictoriaMetrics v1.150.0
```

**构建可复现性**：分别经"模块代理"与"本地源码 replace"两条路径构建，产物 **SHA256 完全一致**（`-trimpath` + 相同的 Go 版本消除了路径与时间戳差异）。

### 4.2 在目标 Linux 机器上校验

```bash
# 1) 校验和
sha256sum -c vmbackup-partition-linux-amd64.sha256

# 2) 可执行性 + 版本串
chmod +x vmbackup-partition-linux-amd64
./vmbackup-partition-linux-amd64 -version
# 期望输出：vmbackup-partition v1.0.1 based-on VictoriaMetrics v1.150.0

# 3) 静态链接确认（无 libc 依赖）
file vmbackup-partition-linux-amd64
ldd  vmbackup-partition-linux-amd64 || true   # 应输出 "not a dynamic executable"

# 4) 参数自检（无需数据目录）
./vmbackup-partition-linux-amd64 -h | head -40
```

> **说明**：本次交付的 binary 是交叉编译产物，已通过"ELF 类型 + 静态链接 + SHA256 + 版本注入"四项静态校验，但**尚未在 Linux 上实际运行**（构建机为 macOS，无容器运行时可用）。请按上述第 2 步在目标机上确认一次；随后按 `docs/03-使用与验证.md` §4 的试运行流程做端到端确认。

### 4.3 安装到各 vmstorage 节点

```bash
# 从构建机分发（3 个节点重复执行）
for h in 10.0.0.11 10.0.0.12 10.0.0.13; do
  scp bin/vmbackup-partition-linux-amd64 root@$h:/usr/local/bin/vmbackup-partition
  ssh root@$h 'chmod +x /usr/local/bin/vmbackup-partition && /usr/local/bin/vmbackup-partition -version'
done
```

## 6. 常见编译问题排查

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| `go: downloading go1.26.x` → 校验失败 | `GOTOOLCHAIN=auto` + `GOSUMDB=off` | 见 §2 坑 1，改用 `GOTOOLCHAIN=local` + 本地安装的工具链 |
| `cannot find module providing package …` | GOPROXY 不可达 | 设置 `GOPROXY=https://goproxy.cn,direct`，或改走 §3.2 的本地源码 replace |
| `go.mod requires go >= 1.26.6` | 本机 Go 版本过低 | 安装 Go 1.26.6+ |
| `unbound variable: GOFLAGS_EXTRA[@]`（仅 macOS 自带 bash 3.2） | bash 3.2 在 `set -u` 下展开空数组的已知行为 | 已在 `scripts/build-linux-amd64.sh` 中用 `${arr[@]+"${arr[@]}"}` 惯用法规避；或改用 `bash` 5.x（`brew install bash`） |
| 产物里含构建机路径 | 忘了 `-trimpath` | Makefile 与脚本已内置 `-trimpath` |
